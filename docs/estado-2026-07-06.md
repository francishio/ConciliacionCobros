### Catálogo de pasarelas (data, ya no enum)
- Tabla `Pasarela` (global, administrable en `/pasarelas`). Los campos
  `proveedor` guardan el `codigo`.
- La config de pasarela va **a nivel establecimiento** (no a nivel cliente): en
  Establecimientos, cada mapeo tiene proveedor + código de terminal + **modo
  (Archivo/API)** + credencial de API cifrada (si API).

### Carga por mes + cobertura
- Columna `periodo` (YYYY-MM) en Cobro/Transaccion. Carga **por fuente**
  (`reemplazarCobrosMes` / `reemplazarTransMes` + `reconciliarMes`): sincronizar
  HIOPOS no pisa los extractos y viceversa.
- Pantalla **Cargar archivos**: vista **anual + matriz** (HIOPOS/pasarelas ×
  meses, celda = cantidad o ·). Al tocar un mes: panel de subida con un input por
  pasarela (modo archivo) + botón **↻ Sincronizar HIOPOS** (trae las ventas del
  mes por API, Exportation ID de Ventas + rango del mes).
- **Cobertura**: por pasarela, cobros HIOPOS vs extracto → conciliada / sin
  extracto / no conciliable.

  **misma tienda** (mismo establecimientoId). El match **manual** queda libre.

## Hecho 2026-10-08 — Rediseño: credenciales por cliente + match por ID de pago

Disparado por NEBULA/DINEGA (Clover): la expo filtrada a **medios integrados** +
el ID de pago de Clover en HIOPOS simplifican el modelo.

- **1 solo Exportation ID** (`ConfigHiopos.expIdVentas`): se eliminó `expIdTiendas`
  y el endpoint `/api/tiendas/sync`. Los establecimientos se crean solos al cargar
  ventas (la expo trae `Cód. Establecimiento` embebido).
- **`CuentaPasarela`** (tabla nueva, RLS): el lugar ÚNICO de credenciales por
  cliente. Una fila por comercio/cuenta (Clover usa token por-MID). Credencial
  cifrada. Pantalla nueva **`/credenciales`** (CRUD; cliente o super admin).
- **`MapeoEstablecimientoPasarela`**: se le sacó `apiCredEnc` (la credencial ya no
  vive acá); queda solo para scope por tienda. La carga lee los modos (archivo/API)
  de `CuentaPasarela`.
- **Match por ID de pago (`Cobro.refPasarela`)**: HIOPOS estampa el payment id de
  Clover en "Datos Transacción" (`EQMBG5HBRVDXP|OK`). Es clave ÚNICA GLOBAL → el
  matcher determinístico la usa PRIMERO y **sin exigir misma tienda**. Así Clover
  concilia con solo cargar credencial + medio (sin mapear establecimiento).
- **Validado e2e con DINEGA (octubre)**: 42 cobros ↔ 81 pagos Clover → **42/42 OK,
  100% DETERMINISTICO, 0 excepciones**, a través del motor real de la app.
- Dev local en **puerto 3200** (`.claude/launch.json`): el 3000 lo ocupa APIs
  BRIDGE. `npm run dev -- -p 3200`.
- PENDIENTE sugerido por el usuario: **rediseñar look&feel** → igualarlo al naranja
  tipo Analytics de las otras apps (ver memoria [[apis-bridge-ui]]).
