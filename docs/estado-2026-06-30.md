## 1. Qué es la app

Sistema multi-tenant de **conciliación de cobros**: cruza los cobros del POS
(HIOPOS/Hioffice) contra las pasarelas de cobro (Payway, MercadoPago, …).

**Stack**: Next.js 14 (app router) · Prisma 5.22 · Neon PostgreSQL · Tailwind ·
TypeScript. Multi-tenant con **RLS** (rol `app_runtime` con RLS + `withTenant`;
`adminDb`/neondb_owner para tareas cross-tenant).

**Dos etapas** (previstas en el modelo: `estadoOp` / `estadoFin` + `Liquidacion`):
- **Etapa 1 — Operativa**: POS ↔ pasarela ("¿la venta cobrada tiene su
  transacción aprobada por el mismo importe?"). Es lo que ya funciona.
- **Etapa 2 — Financiera**: pasarela ↔ liquidación/banco ("¿el dinero se
  acreditó, con la comisión correcta?"). Futuro (falta data).

**Decisiones de diseño acordadas** (ver `docs/findings-payconcil.md` y abajo):
- La **unidad de conciliación** apunta a ser `tienda × pasarela × mes`.
- **Validación de cobertura**: HIOPOS trae los cobros de todas las pasarelas de
  la tienda; al cargar, el sistema debe avisar si falta el extracto de alguna.
- **Período mensual** como eje: cargar en bloques mensuales, dashboard parado en
  un mes. (Todavía no implementado.)

## 3. Lo hecho en esta sesión

### UX / reskin
- Design system PayConcil (tokens dark, `.pc-panel`/`.pc-badge`/`.pc-input`).
- Shell (sidebar navegable + topbar), dashboard re-skineado con KPI cards.
- Dashboard: **desglose por establecimiento** (tabla con % auto por tienda).
- **Conciliación manual** (`/manual`): grilla doble seleccionable, barra flotante
  con diferencia de monto y "Confirmar match" (reutiliza `confirmarMatchManual`).

### Establecimientos + mapeo de pasarelas
- Modelo `MapeoEstablecimientoPasarela` (tienda ↔ código de establecimiento/
  terminal por proveedor). Un código pertenece a una sola tienda; una tienda
  puede tener varios (varias terminales).
- Pantalla en **tabla** (Código, Tienda, Dirección, Población, Provincia, Grupo);
  cada fila se despliega para mapear pasarelas (chips + alta/baja).

### Configuración (credenciales)
- Modelo `ConfigHiopos` por cliente: usuario + **contraseña cifrada**
  (AES-256-GCM, clave en `.env` → `CONFIG_ENC_KEY`) + **dos Exportation IDs**
  (Ventas/Cobros y Tiendas). La password nunca se devuelve por la API.

### Import de tiendas desde HIOPOS + FIX importante del Bridge
- **Hallazgo (validado contra el HIOPOS real de Rochino)**: el `launch` del
  Bridge devuelve un **array** de block-actions con `exportedDocs` **dentro** de
  cada elemento (no en la raíz). El cliente leía `data.exportedDocs` → **siempre
  0 docs**. Ese era el motivo real de la "ingesta vacía por Bridge" (más que la
  intermitencia). **Arreglado** en `src/ingesta/hiopos/bridge.ts`.
- Botón **↻ Sincronizar HIOPOS** en Establecimientos: trae el catálogo de tiendas
  por API (Exportation ID de Tiendas) y hace upsert.
- Modelo `Establecimiento` ampliado con datos reales del catálogo:
  `nombreFiscal, cuit, direccion, localidad, provincia, codigoPostal, grupo,
  telefono, email, raw`. Columnas reales de la expo de Tiendas:
  `Cód. Tienda; Tienda; Nombre Fiscal; Nif; Dirección; Población; Provincia;
  Código Postal; Grupo Tiendas`. Rochino = **5 tiendas** (cód 1, 11, 17, 18, 19).

### Ingesta HIOPOS
- El parser de cobros ahora lee **hora opcional** (celda `Fecha` con hora o
  columna `Hora`). Habilita, a futuro, estrechar la ventana del matching fuzzy.
  (Falta que la exportación de HIOPOS incluya la hora.)

## 6. Notas técnicas / gotchas

- **Windows + Prisma**: `prisma generate` falla con `EPERM` si `npm run dev` está
  corriendo (lockea el `.dll` del motor) → **frenar el dev** antes de regenerar.
  Para aplicar migraciones sin regenerar: `prisma migrate deploy` (no toca el
  cliente, no choca con el dev).
- **Tabla tenant-scoped nueva** → SIEMPRE agregar migración RLS a mano
  (`ENABLE ROW LEVEL SECURITY` + `CREATE POLICY tenant_aislamiento`); `migrate
  dev` solo agrega el grant vía DEFAULT PRIVILEGES.
- **`CONFIG_ENC_KEY`** está en `.env` (gitignore la excluye). Al desplegar
  (Netlify) hay que cargar la MISMA clave, sino no descifra las credenciales.
  Rotarla invalida los secretos guardados.
- **Ejecutar** en local: `cd C:\CLAUDE\ConciliacionCobros` → `npm run dev` →
  http://localhost:3000 (sin login todavía; el cliente se elige por nombre).
